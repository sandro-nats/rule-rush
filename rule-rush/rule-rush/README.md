## გაშვება ლოკალურად

საჭიროა Node 22.13+ (SQLite ჩაშენებულია, npm პაკეტები არ სჭირდება).

```bash
cd rule-rush
npm run dev          # DEV_AUTH=1: შესვლა სახელით, Telegram-ის გარეშე
# გახსენი http://127.0.0.1:8080
npm test             # 16 ლოგიკის + 19 სერვერის ტესტი
```

`DEV_AUTH` მხოლოდ ლოკალური ტესტისთვისაა. ის ქმნის უარყოფითი ID-ის მომხმარებლებს და **არასდროს უნდა ჩაირთოს პროდუქციაში**.

## პროდუქციაში გაშვება (Telegram-ით)

1. **ბოტი:** BotFather → `/newbot`. დაიმახსოვრე ტოკენი და username.
2. **დომენი:** Telegram Login მუშაობს მხოლოდ HTTPS დომენზე. BotFather → `/setdomain` → შენი დომენი.
3. **Mini App (სურვილისამებრ):** BotFather → `/newapp` (ან ბოტის Menu Button) → იგივე URL. Mini App-ში მოთამაშე ავტომატურად შედის `initData`-ით.
4. **ჰოსტინგი:** სერვერი არის ერთი Node პროცესი (სტატიკა + API), ამიტომ Netlify-ის სტატიკური ჰოსტინგი აქ არ კმარა. გამოდგება ნებისმიერი VPS/Fly.io/Railway/Render, Nginx ან Caddy-ს უკან HTTPS-ით. ბაზის ფაილი უნდა იყოს მუდმივ დისკზე.
5. **გარემოს ცვლადები:**

| ცვლადი | აუცილებელია | აღწერა |
|---|---|---|
| `BOT_TOKEN` | დიახ | ბოტის ტოკენი (ხელმოწერის შესამოწმებლად; არასდროს გაუგზავნო კლიენტს) |
| `BOT_USERNAME` | დიახ | ბოტის username (ლოგინის ღილაკისთვის) |
| `ADMIN_TOKEN` | დიახ | გრძელი შემთხვევითი სტრიქონი admin API-სთვის. თუ არ არის, admin API გამორთულია |
| `COOKIE_SECURE=1` | დიახ HTTPS-ზე | cookie მხოლოდ HTTPS-ით |
| `TRUST_PROXY=1` | თუ proxy-ს უკანაა | რეალური IP-ისთვის (rate limit) |
| `DB_PATH` | სასურველია | ბაზის ფაილი (ნაგულისხმევი `data/rulerush.db`) |
| `DAILY_TRIALS` | არა | მცდელობა დონეზე დღეში (ნაგულისხმევი 1) |
| `SEED_SECRET` | არა | თუ არ არის, ერთხელ გენერირდება და ბაზაში ინახება (ასე დღის seed რესტარტზე არ იცვლება) |
| `PORT`, `HOST` | არა | 8080 / 127.0.0.1 |

`npm start` — გაშვება.

## როგორ მუშაობს დღის გამოწვევა

1. მოთამაშე ირჩევს დონეს და აჭერს "დღის გამოწვევას". სერვერი ქმნის `runs` ჩანაწერს და უგზავნის **დღიურ seed-ს** (HMAC სერვერის საიდუმლოთი, დონე+თარიღზე). იმავე დონეზე ყველა მოთამაშე იგივე სამიზნეებს იღებს.
2. **მცდელობა იხარჯება დაწყებისთანავე.** თუ მოთამაშე რაუნდს მიატოვებს ან აპიდან გავა, მცდელობა დახარჯულია. ეს ხელს უშლის seed-ის "გასინჯვას" და გადათამაშებას. ლიმიტი ბაზის `UNIQUE` შეზღუდვითაა დაცული, ამიტომ პარალელური მოთხოვნებით ვერ გაუვლიან.
3. რაუნდის ბოლოს კლიენტი აგზავნის **მხოლოდ შეხებების სიას** `[{t,x,y}]`. სერვერი იმავე `core.js`-ით თავიდან ათამაშებს და **ქულას თავად ითვლის**. კლიენტის ქულა მხოლოდ შესადარებლად გამოიყენება.
4. შედეგი: `verified` (ლიდერბორდზე), `verified + pending` (ხელით შემოწმებამდე ლიდერბორდზე არ ჩანს), ან `rejected` (უარყოფილი; მიზეზი კლიენტს არ ეგზავნება, რომ ჩითერმა არ მოარგოს).
5. დღის საზღვარი **UTC 00:00** (თბილისში 04:00).

## Anti-cheat: რას იჭერს და რას არა

**იჭერს და უარყოფს:** ყალბ ქულას, არაადამიანურად სწრაფ რეაქციას (<100 ms), სერვერზე გაზომილ დროზე უფრო სწრაფ გაგზავნას, დროის/კოორდინატების გაყალბებას, Hard-ში შეცდომის შემდეგ გაგზავნილ შეხებებს, სხვისი რაუნდის გაგზავნას, ორჯერ გაგზავნას, 90 წამზე გვიან გაგზავნას.
**აფლაგებს ხელით შესამოწმებლად** (ლიდერბორდზე არ ჩანს, სანამ დაამტკიცებ): ზედმეტად "მეტრონომივით" თანაბარ რეაქციებს და შეხებების ზედმეტად სწრაფ ჯაჭვებს.

**რასაც ვერ იჭერს (გაითვალისწინე პრიზების გაცემამდე):**
- **ბოტი ადამიანური ვარიაციით.** ბრაუზერიდან გაშვებულმა სკრიპტმა, რომელიც სამიზნეებს კითხულობს და შემთხვევით დაგვიანებით აჭერს, შეიძლება გაიაროს. ჩემმა სატესტო ბოტმა ეს გაიარა (მისი ქულა 16k, 100% სიზუსტე, 35/35 იდეალური). ამიტომ **ნებისმიერი პრიზიანი ადგილი გაცემამდე ხელით უნდა შეამოწმო**: `GET /admin/runs/:id` გაძლევს შეხებების ნედლ მონაცემს და ზედა ადგილების რეალურ ადამიანურობას (არარეალური სიზუსტე, ერთნაირი ტრაექტორიები) თვალით დაინახავ.
- **seed-ის გაზიარება.** ვინც რაუნდს იწყებს, seed-ს ხედავს და მეგობარს შეუძლია გადასცეს, რომ მან იგივე განლაგება წინასწარ ივარჯიშოს. შემდეგი გამაგრება: სამიზნეების სერვერიდან თანდათან გაცემა რაუნდის განმავლობაში.
- **მრავალი ანგარიში.** Telegram-ის ანგარიშის გახსნა იაფია. ზედა ადგილების შემოწმებისას დააკვირდი ახალ ანგარიშებს.

## სპონსორების პრიზების პროცესი (admin API)

`Authorization: Bearer $ADMIN_TOKEN` + `Content-Type: application/json`.

```bash
# 1) სპონსორი და პრიზი (ამ დონის დღიური ლიდერბორდის 1–3 ადგილი)
curl -X POST $URL/admin/sponsors -H "$AUTH" -H "$JSON" -d '{"name":"Acme","url":"https://acme.example"}'
curl -X POST $URL/admin/prizes   -H "$AUTH" -H "$JSON" -d '{"sponsorId":1,"tier":"hard","period":"day","startsDay":"2026-11-01","endsDay":"2026-11-30","rankFrom":1,"rankTo":3,"title":"$20 gift card"}'

# 2) საეჭვო რაუნდების გადახედვა და გადაწყვეტილება
curl $URL/admin/reviews -H "$AUTH"
curl -X POST $URL/admin/reviews -H "$AUTH" -H "$JSON" -d '{"runId":12,"decision":"approve","note":"..."}'   # ან "reject"

# 3) დასრულებული დღის (ან კვირის, key = ორშაბათის თარიღი) შეჯამება -> გამარჯვებულთა ჩანაწერები
curl -X POST $URL/admin/finalize -H "$AUTH" -H "$JSON" -d '{"tier":"hard","period":"day","key":"2026-11-05"}'

# 4) გამარჯვებულების ნახვა (tg_id, username კონტაქტისთვის) და სტატუსის განახლება
curl "$URL/admin/awards?status=pending" -H "$AUTH"
curl -X POST $URL/admin/awards/5 -H "$AUTH" -H "$JSON" -d '{"status":"delivered","note":"კოდი გაიგზავნა"}'
```

`finalize` არ მუშაობს დაუსრულებელ პერიოდზე და უარს ამბობს, სანამ ამ პერიოდში განუხილველი საეჭვო რაუნდებია (გამარჯვებული ვერ დარჩება ხელით შემოწმების გარეშე). განმეორებით გაშვება დუბლიკატებს არ ქმნის. მოთამაშე თავის პრიზებს ხედავს მენიუში. ბანი: `POST /admin/users/ban {"tgId":..}`.

## უსაფრთხოების შენიშვნები

- ტოკენი cookie-ში `HttpOnly; SameSite=Lax`, ბაზაში მხოლოდ მისი SHA-256 ინახება.
- ყველა POST მოითხოვს `application/json`-ს და same-origin-ს (CSRF).
- სტატიკური ფაილები whitelist-ითაა: სერვერის კოდი და ბაზა არ ჩანს. Content-Security-Policy ჩართულია.
- მომხმარებლის სახელები UI-ში ყოველთვის როგორც ტექსტი ჩაისმება (`textContent`), არა HTML.
- ლიდერბორდზე ჩანს მხოლოდ სახელი, გვარის პირველი ასო და ავატარი. username და Telegram ID მხოლოდ admin-ს ჩანს.
- Rate limit მეხსიერებაშია (ერთი პროცესი). რამდენიმე სერვერზე გაშვებისას გადაიტანე Redis-ში, ბაზა კი Postgres-ზე.

## ცნობილი შეზღუდვები / შემდეგი ნაბიჯები

1. **რეალური Telegram-ით არ გამიტესტავს.** Login Widget-ისა და `initData`-ის ხელმოწერები შემოწმებულია Telegram-ის დოკუმენტირებული ალგორითმით დაწერილ ტესტებში, მაგრამ ცოცხალი ბოტი და დომენი ჯერ არ ყოფილა. პირველი რეალური ტესტი უნდა გააკეთო შენი ბოტით.
2. **ქართული ტექსტები** მშობლიური ენის მატარებელმა გადაამოწმოს (განსაკუთრებით წესების ბრუნვები).
3. Admin UI არ არის, მხოლოდ API.
4. Stars-ით ყიდვა (დამატებითი მცდელობა/კოსმეტიკა): ბუნებრივად ჯდება `runs.attempt_no` + `DAILY_TRIALS` ლოგიკაში, მაგრამ ეს თანხა არც ერთ პრიზში არ უნდა მონაწილეობდეს.
5. იურიდიულად: უფასო მონაწილეობა და სპონსორის პრიზი მნიშვნელოვნად ამცირებს რისკს, მაგრამ პრიზების წესები (ვინ, რა პირობებით, ასაკი, ქვეყნები, გადასახადი) იურისტმა უნდა გაწეროს. ეს ჩემი შეფასება არ არის და იურიდიულ რჩევას არ ცვლის.
6. ფერთა სიბრმავის რეჟიმი (სამიზნეზე დამატებითი ნიშანი) ჯერ არ არის.
